# Пояснительная записка к проекту «Pakost Chatting»

**Тема:** собственный мессенджер для друзей — нативный клиент и сервер на Rust.
**Тип проекта:** учебный программный проект.
**Стоимость:** 0 ₽ (открытый код, бесплатный хостинг, свободные шрифты).

---

## 1. Актуальность

Для совместных игр и общения компаниям нужен свой чат: Discord избыточен,
требует аккаунтов и платных бустов, а данные лежат на чужом сервере. Готовые
решения либо весят сотни мегабайт (Electron/WebView), либо не дают контроля над
историей. «Круг» решает задачу минимально: один сервер на Rust, два клиента
(окно и терминал), вся история — на своём диске, установка — распаковка архива.

## 2. Цель и задачи

**Цель:** разработать работающий мессенджер для небольшой группы людей,
который можно бесплатно поднять в интернете и который не зависит от браузерных
движков.

**Задачи:**

1. Спроектировать бинарный протокол с версией и ограничениями.
2. Реализовать сервер: вход, личные чаты, прочтения, история, rate limit.
3. Реализовать сетевой слой клиента с автопереподключением.
4. Сделать нативное окно без WebView (свой рендер и шрифты).
5. Сделать консольный клиент на том же ядре.
6. Обеспечить бесплатное развёртывание (Render, Oracle Always Free, туннель).
7. Покрыть критичные сценарии автотестами.
8. Заложить основу для портирования на старые консоли.

## 3. Функциональность

- **Вход.** Ник, пароль, код приглашения. Пароль хранится как соль + SHA-256
  (4096 итераций), регистрация возможна только по инвайту.
- **Личные чаты.** Список людей, открытие переписки, отметки прочтения,
  счётчик непрочитанных.
- **Сообщения.** История на диске, последовательные номера, время, переносы
  строк, группировка подряд идущих сообщений, разделители дат.
- **Присутствие.** Люди онлайн/офлайн, «печатает…», статус соединения,
  задержка.
- **Сеть.** TCP и WebSocket, пинг/понг, таймаут простоя, переподключение с
  экспоненциальной паузой, очередь команд.
- **Интерфейсы.** Нативное окно (1200×800, тёмная тема, мышь и клавиатура) и
  консольный клиент с командами.
- **Развёртывание.** Docker, `render.yaml`, инструкция для Oracle, туннель
  Cloudflare, скрипты сборки и запуска.

## 4. Архитектура и технологии

Проект — workspace из пяти крейтов:

| Крейт | Назначение | Ключевые технологии |
|---|---|---|
| `krug-core` | протокол, модель, кадры, SHA-256 | `no_std` + `alloc`, без зависимостей |
| `krug-server` | личные чаты, история, TCP/WS | потоки, `mpsc`, файлы, `tungstenite` |
| `krug-client` | соединение и состояние | `Arc<Mutex<State>>`, rustls |
| `krug-cli` | терминальный клиент | ANSI, `chrono` |
| `krug-gui` | окно и рендер | `winit`, `softbuffer`, `fontdue` |

**Почему Rust.** Как Discord, переписавший часть клиента на Rust, проект
получает нативный бинарник без прослойки браузера: предсказуемая память,
отсутствие JS-рантайма, простой перенос на другую платформу. Ядро протокола
специально не использует `std`, чтобы его можно было собрать под консоль.

**Рендер.** Кадр — `Vec<u32>` (RGB). Примитивы (скругления, круги, градиенты,
треугольники для «бумажного самолётика», текст) реализованы вручную с
альфа-смешиванием; шрифт Inter растеризуется `fontdue` и кэшируется по глифам.
Обои чата — светлый градиент с мелким узором из точек; сообщения — облака
Telegram-стиля с хвостиками, временем и цветными именами. Фон и узор
кэшируются, поэтому перерисовка окна не тормозит. Тот же буфер сохраняется в
PNG собственного производства (zlib «stored» + CRC32/Adler32), поэтому вёрстку
можно проверять без запуска окна.

**Потоки.** Сервер: поток на соединение + поток-писатель на сокет, общее
состояние под мьютексом. Клиент: один фоновый поток на соединение, интерфейс
читает снимок состояния и не блокируется.

## 5. Протокол

Кадр: `u32` длина (little-endian) + `u8` операция + поля. Строки — `u16` длина +
UTF-8. Версия протокола — 1, при несовпадении сервер вежливо отказывает.

Клиент → сервер: `Login`, `SendMessage`, `Join`, `Leave`, `History`, `Typing`,
`OpenDirect`, `Read`, `Ping`, `Logout`.

Сервер → клиент: `Welcome`, `Error`, `Rooms`, `Joined`, `Message`, `Presence`,
`Typing`, `History`, `Pong`.

Ограничения: кадр ≤ 64 КБ, сообщение ≤ 4 КБ, ник ≤ 48 байт, 64 чата,
100 сообщений в одном ответе истории.

## 6. Безопасность и ограничения

- соль + 4096 итераций SHA-256, сравнение хешей и инвайта за постоянное время;
- rate limit на сообщения и индикатор набора;
- вырезание управляющих символов и ограничение размеров;
- отдельные права: сервер не отдаёт чужие пароли и соли клиенту;
- TLS только на транспорте (`wss://`); «из коробки» сквозного шифрования нет.

Проект не претендует на защиту государственной тайны: это дружеский сервер.
Для публичного размещения рекомендуется `wss://` (Render/Cloudflare) или VPN.

## 8. Тестирование

- юнит-тесты ядра: SHA-256 на известных векторах (включая 1 млн байт), кадры,
  все операции, границы полей;
- тесты сервера: регистрация, пароль, инвайт, нумерация сообщений;
- сквозные тесты: настоящий сервер + два клиента, доставка сообщений,
  присутствие, перезапуск сервера и сохранение истории, WebSocket, health-check;
- визуальная проверка: рендер окна в PNG (`--screenshot`).

Запуск: `cargo test`.

## 9. Портирование на старые консоли

Ядро (`krug-core`) не зависит от ОС: собирается без `std`, использует только
`alloc`. Это значит, что протокол и модель можно переиспользовать на консоли,
заменив транспорт, ввод и вывод. Подробный план, цели и честные ограничения —
в [PORTING.md](PORTING.md).

## 10. Развитие

1. Звонки (микрофон, буфер, звук) — следующий шаг.
2. Файлы и картинки, реакции, ответы.
3. Сквозное шифрование личных сообщений.
4. Консольный клиент-порт (PSP/Vita) как проверка переносимости.
5. Уведомления и статусы (не беспокоить).

## 11. Вывод

Разработан полностью рабочий мессенджер «Круг»: сервер на Rust с историей на
диске, нативное окно без WebView и консольный клиент. Проект бесплатен,
разворачивается на бесплатном хостинге, проверен автотестами и имеет
архитектурный задел под портирование на слабое железо и консоли.
