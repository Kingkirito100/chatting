# Портирование «Круга» на старые консоли

Коротко: **ядро готово к переносу, клиент — нет.** Ниже честно, что уже
сделано, чего не хватает и сколько это стоит по времени.

## Что уже переносимо

`krug-core` собирается без `std` (нужен только `alloc`):

```bash
cargo build -p krug-core --no-default-features
```

Внутри — весь протокол, модель сообщений, кадры и SHA-256. Никаких сокетов,
файлов, потоков и времени: всё это передаётся снаружи. Значит, на консоли
достаточно реализовать четыре вещи:

1. **Транспорт** — TCP-клиент (обычно lwIP) и чтение/запись кадров.
2. **Память** — аллокатор под `alloc` (или заранее выделенные буферы).
3. **Ввод** — геймпад/клавиатура → строка сообщения.
4. **Вывод** — кадр в память консоли + шрифт.

Пятый пункт — время: `Message.ts_ms` приходит с сервера, клиенту часы не нужны.

## Чего не хватает

- **TLS.** На старых консолях нет rustls/webpki. Варианты: сервер в локальной
  сети без TLS, либо отдельный мост (ПК/роутер), который держит `wss://`.
- **Потоков и мьютексов.** Клиент придётся переписать на кооперативный
  state machine: `poll()` раз в кадр, без блокирующих вызовов.
- **Шрифта.** Inter — около 400 КБ TTF, для PSP это заметно. Нужен урезанный
  битмап-шрифт (8×16, кириллица + латиница) и свой рендер.
- **Памяти.** История на 400 сообщений — это сотни килобайт. На консоли
  держим 20–30 сообщений и подгружаем историю по запросу.

## Цели и реальность

| Платформа | Реалистичность | Что нужно |
|---|---|---|
| **PSP** | высокая | `rust-psp`, lwIP, 32 МБ RAM, WiFi есть |
| **PS Vita** | средняя | VitaSDK, Rust через C ABI, больше памяти |
| **Dreamcast** | средняя | KallistiOS, Rust как статическая библиотека, сеть через BBA |
| **PS2** | низкая | ps2dev — C/C++, зрелого Rust-таргета нет |
| **DS/3DS** | низкая | TCP есть, но памяти и экранов мало; нужен свой UI |
| **Xbox 360 / PS3** | очень низкая | закрытые тулчейны, Rust не собирается |

Начинать стоит с **PSP**: у `rust-psp` живое сообщество, есть WiFi и
понятный фреймбуфер. Это же лучший тест того, что ядро действительно
переносимо, а не «переносимо на бумаге».

## План работ

1. **Неделя 1.** Вынести из `krug-client` чистую машину состояний:
   `feed(bytes)`, `tick(now_ms)`, `outgoing()`. Без сокетов и потоков.
   Покрыть тестами на тех же сценариях, что e2e.
2. **Неделя 2.** Собрать `krug-core` под `rust-psp`, поднять lwIP, добиться
   `Login/Welcome` на реальной консоли или эмуляторе PPSSPP.
3. **Неделя 3.** Битмап-шрифт, экран чата 480×272, ввод через OSK (экранная
   клавиатура) или геймпад.
4. **Неделя 4.** Сборка ISO/CSO, скрипт запуска, проверка на железе.

## Архитектурная граница

Сейчас в клиенте три слоя:

```
krug-core      протокол и модель          (уже no_std)
krug-client    соединение и состояние     (std: потоки, сокеты, время)
krug-gui/cli   ввод и вывод
```

Для консоли нужен четвёртый вариант: `krug-console` — тот же `krug-client`,
но с `Transport`-трейтом вместо `TcpStream` и без фонового потока. Логику
состояния (комнаты, сообщения, присутствие) можно переиспользовать почти
целиком, если убрать `Arc<Mutex<..>>` в пользу `&mut State`.

## Что уже помогает

- `ClientKind::Console` в протоколе — сервер знает, что подключилась консоль;
- `krug-core` не тянет `serde`, `tokio` и `std`;
- сообщения — плоские структуры без указателей, легко сериализуются;
- PNG-скриншоты позволяют проверять вёрстку без консоли;
- протокол версионирован: старый клиент получит понятный отказ, а не мусор.

## Вывод

Портирование на PSP — это 3–4 недели инженерной работы, а не «пересобрать
одной командой». Но главное уже сделано: логика чата не зависит от
операционной системы, а сервер умеет говорить с кем угодно, кто знает
бинарный протокол.
